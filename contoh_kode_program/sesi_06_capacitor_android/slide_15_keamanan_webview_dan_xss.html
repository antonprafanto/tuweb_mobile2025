SLIDE 15 • KEAMANAN APLIKASI HYBRID

Keamanan WebView & Bahaya Cross-Site Scripting (XSS)

Mengapa celah XSS pada aplikasi mobile hybrid jauh lebih berbahaya dibanding web biasa, dan bagaimana mencegahnya.

📘 PANDUAN PRAKTIKUM & MITIGASI KERENTANAN HYBRID
🛠️ Alat yang Digunakan: Google Chrome (berkas ini), DevTools (F12), Visual Studio Code (pemeriksaan berkas index.html dan template Vue).
🎯 Cara Menguji Interaksi: Ketikkan skrip berbahaya (seperti <script> atau tag gambar rusak <img src=x onerror=...>) pada kotak masukan di panel kanan. Amati bagaimana perlakuan Vue secara default menetralkan kode jahat tersebut menjadi teks murni yang aman.
💡 Bahaya Berlipat Ganda: Pada website biasa, serangan XSS mencuri cookies. Namun pada aplikasi hybrid, kode JavaScript jahat dapat mengeksploitasi Capacitor Bridge untuk membaca berkas rahasia di penyimpanan ponsel korban atau melacak lokasi GPS secara diam-diam!

⚠️ Mengapa XSS di Mobile Sangat Fatal?

Di website biasa, XSS hanya mencuri cookie peramban. Namun di aplikasi hybrid Capacitor, kode JavaScript jahat yang berhasil disuntikkan dapat memanggil Runtime Bridge native untuk membaca file di penyimpanan memori HP, mengakses kontak, atau melacak koordinat GPS korban!

🛡️ 3 Perisai Utama Pengembang UT:

  1. Hindari v-html: Selalu gunakan interpolasi kurung kurawal ganda {{ "{{" }} data {{ "}}" }} yang otomatis men-sanitize karakter HTML berbahaya.
  2. Content Security Policy (CSP): Batasi domain skrip eksternal di tag <meta http-equiv="Content-Security-Policy">.
  3. Skema https://localhost: Capacitor menyajikan bundel lokal menggunakan protokol HTTPS internal yang aman.

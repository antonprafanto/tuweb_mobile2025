Manajemen Hak Akses Runtime (Runtime Permissions)

Mekanisme perizinan dinamis Android: Alur checkPermissions() dan requestPermissions() pada TypeScript.

📘 PANDUAN PRAKTIKUM & SIMULASI DIALOG IZIN RUNTIME
🛠️ Alat yang Digunakan: Google Chrome (berkas ini), DevTools (F12), Smartphone Android Fisik.
🎯 Cara Menguji Interaksi: Klik tombol "📸 Buka Kamera Scanner KTM" di simulator ponsel sebelah kanan. Perhatikan bagaimana dialog izin sistem Android muncul secara kontekstual, lalu uji respon aplikasi saat Anda memilih tombol "Hanya Saat Aplikasi Digunakan" vs "Jangan Izinkan".
💡 Prinsip Desain UX Mobile: Jangan meminta izin hardware saat pertama kali aplikasi diinstal (*cold launch*). Mintalah izin hanya ketika pengguna secara sengaja menekan tombol fitur (misalnya saat mahasiswa hendak memindai presensi QR code).

🔐 Alur Pengecekan Izin di Capacitor

Sejak Android 6.0 (Marshmallow), aplikasi tidak boleh langsung membuka hardware sensitif tanpa izin sadar dari pengguna saat runtime.

import { Camera } from '@capacitor/camera'; // 1. Cek status izin terkini: const check = await Camera.checkPermissions(); if (check.camera !== 'granted') { // 2. Jika belum diizinkan, minta dialog pop-up: const req = await Camera.requestPermissions(); if (req.camera !== 'granted') { alert('Izin kamera ditolak! Buka Pengaturan HP.'); return; } } // 3. Izin sah, jalankan kamera: const image = await Camera.getPhoto({...});
💡 Status Izin yang Mungkin Diterima:
  • granted: Akses penuh disetujui.
  • prompt: Pengguna belum pernah ditanya (tampilkan dialog).
  • denied: Pengguna menolak (jangan tanya berulang kali, arahkan ke App Settings).

Evolusi Runtime: Apache Cordova vs Capacitor

Mengapa ekosistem mobile modern meninggalkan pendekatan 'Kotak Hitam' Cordova dan beralih ke filosofi 'Source-First' Capacitor.

PENDEKATAN LAMA (LEGACY)

Apache Cordova (Black Box)

Proyek native dianggap sebagai artefak sekali pakai yang di-generate ulang setiap kali build.

  • Folder platforms/: Di-ignore dari Git. Mahasiswa dilarang mengedit file Java secara manual karena akan tertimpa saat build ulang!
  • Konfigurasi XML Kuno: Bergantung pada berkas raksasa config.xml yang rentan bentrok (*conflict*).
  • Instalasi Global: Wajib menginstal npm install -g cordova yang kerap menimbulkan konflik hak akses admin/sudo.
  • Debugging Terbatas: Mahasiswa terisolasi dari lingkungan asli Android Studio.
STANDAR INDUSTRI SEKARANG

Capacitor (Source-First)

Folder android/ adalah artefak kode sumber asli yang di-commit ke repositori Git.

  • Folder android/: Milik pengembang seutuhnya! Anda bebas membuka di Android Studio, menambah SDK bank, atau mengedit Java/Kotlin sesuka hati.
  • Konfigurasi TypeScript Modern: Dikelola bersih via capacitor.config.ts dengan type safety.
  • Tanpa Instalasi Global: Dijalankan langsung via npx cap menggunakan paket lokal proyek.
  • Plugin Berbasis NPM & ES6: Plugin resmi diimpor layaknya pustaka JavaScript modern biasa.

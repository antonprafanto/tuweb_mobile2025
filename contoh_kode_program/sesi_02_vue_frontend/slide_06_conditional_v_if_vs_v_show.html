Conditional Rendering: v-if (Bongkar Pasang DOM) vs v-show (CSS Toggle)

Membedah perbedaan performa memori dan rendering untuk aplikasi perangkat bergerak.

💡 Panduan Ramah Pemula:
• Alat yang Digunakan: Buka berkas ini di Google Chrome (klik ganda berkas HTML).
• Uji Mode Mobile: Tekan F12 lalu Ctrl + Shift + M untuk simulasi layar ponsel.
• Eksperimen Bukti Nyata: Buka tab Elements (F12) di Chrome DevTools. Klik tombol Alihkan Tampilan dan saksikan: pada v-if elemen HTML benar-benar lenyap dari pohon kode, sedangkan pada v-show elemennya tetap ada namun disembunyikan lewat CSS!

DIREKTIF v-if

Real DOM Destruction

Jika kondisi bernilai false, elemen benar-benar dicabut dari memori DOM pohon browser.

📦 Elemen ini ada di dalam DOM karena v-if bernilai TRUE.
🚫 Elemen telah DIBONGKAR dari DOM (Digantikan comment placeholder).

Pemeriksaan DOM riil:
Elemen ditemukan di DOM? {{ domVIfAda ? 'YA (Ada di DOM)' : 'TIDAK (Dihapus dari DOM)' }}

DIREKTIF v-show

CSS Display Toggle

Elemen selalu tetap berada di DOM, Vue hanya memanipulasi CSS display: none;.

👁️ Elemen ini selalu ada di DOM! (Hanya berganti gaya CSS display).

Pemeriksaan DOM riil:
Elemen ditemukan di DOM? {{ domVShowAda ? 'YA (Selalu ada di DOM)' : 'TIDAK' }}

⚡ Komparasi Kinerja untuk Smartphone (Hemat Baterai & CPU)

Kriteria Komparasi v-if v-show
Biaya Awal (*Initial Render*) Rendah (Jika false, tidak dirender sama sekali). Tinggi (Semua dirender sejak awal ke memori).
Biaya Alih (*Toggle Cost*) Tinggi (DOM harus di-create dan di-destroy). Sangat Rendah (Hanya ganti properti CSS).
Rekomendasi Pemakaian Mobile Halaman/Modal yang jarang dibuka (misal: Logout Dialog, Menu Admin). Komponen yang sering di-toggle (misal: Tab Bar, Accordion FAQ, Dark Mode).

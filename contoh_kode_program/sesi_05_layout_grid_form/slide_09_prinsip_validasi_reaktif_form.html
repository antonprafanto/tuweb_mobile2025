Prinsip Validasi Reaktif: Dirty, Touched, & Umpan Balik Instan

Memahami siklus status kolom masukan agar pesan error tidak langsung menakuti pengguna sebelum mereka sempat mengetik.

📘 PANDUAN PRAKTIKUM & EKSPLORASI MANDIRI
🛠️ Alat yang Digunakan: Google Chrome / Peramban Modern (cukup klik ganda berkas HTML ini), DevTools (F12).
🎯 Cara Menguji Interaksi: 1. Amati status awal: Pristine: true, Dirty: false, Touched: false.
2. Klik kolom nama lalu ketik 1 huruf 'A': Amati Dirty berubah menjadi true.
3. Klik di luar kolom input (event Blur): Amati Touched menjadi true dan pesan galat merah muncul karena panjang huruf < 3!
💡 Apa yang Terjadi di Balik Layar: Pola UX industri memisahkan status touched (apakah pengguna sudah pernah berinteraksi dan keluar) dengan isValid (apakah nilai sah). Ini mencegah formulir langsung berwarna merah saat halaman baru pertama kali dimuat.

💡 Aturan UX Terbaik: Jangan tampilkan teks merah saat kolom masih pristine (belum disentuh). Munculkan pesan error hanya jika sudah touched (sudah diklik keluar) dan datanya invalid!

🧠 3 Status Dasar Kolom Masukan (Input States)

Status Artinya Kapan Muncul?
Pristine Murni / Belum pernah diubah sama sekali. Saat formulir pertama kali dibuka.
Dirty Kotor / Pengguna sudah mengetik 1 karakter. Saat event @ion-input terpicu.
Touched Tersentuh / Kursor sudah keluar dari input (Blur). Saat event @ion-blur terpicu.

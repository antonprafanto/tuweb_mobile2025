Siklus Hidup Masuk: ionViewWillEnter vs ionViewDidEnter

Membedah mengapa onMounted() standar Vue tidak cukup untuk aplikasi mobile yang menyimpan halaman di memori stack.

📘 PANDUAN PRAKTIKUM & SIKLUS HIDUP MASUK

🛠️ Alat yang Digunakan: Google Chrome / Simulator Ponsel.

🎯 Cara Menguji Interaksi: 1. Klik tombol "1. Kunjungan Pertama Kali": perhatikan urutan pemanggilan di terminal hitam (Vue: onMounted $\rightarrow$ Ionic: ionViewWillEnter $\rightarrow$ ionViewDidEnter).
2. Sekarang klik tombol "2. Kembali ke Halaman Ini" (simulasi pengguna menekan tombol Back).
3. Perhatikan peringatan kuning: onMounted() DILEWATI karena komponen sudah di-cache oleh stack! Namun ionViewWillEnter() tetap dipanggil!

💡 Apa yang Terjadi di Balik Layar: Inilah jebakan terbesar bagi pemula di aplikasi mobile. Jika Anda memanggil API data KRS hanya di dalam onMounted(), data mahasiswa tidak akan pernah ter-update saat kembali dari layar lain. Gunakan onIonViewWillEnter() untuk memutakhirkan state reaktif setiap kali layar kembali aktif.

📐 Garis Waktu Eksekusi: Kunjungan Pertama (Create DOM) vs Kunjungan Kembali (From Stack Cache)

⚠️ Perhatikan: Pada kunjungan ke-2, onMounted() TIDAK BERJALAN karena komponen sudah ada di cache! Hanya hook Ionic yang terpanggil.

📋 Karakteristik Lifecycle Hook Masuk

Hook Kapan Terpicu? Penggunaan Ideal
onMounted() Hanya 1x saat DOM pertama dibuat. Konfigurasi plugin pihak ketiga statis.
ionViewWillEnter Tepat SEBELUM animasi transisi dimulai. Memuat ulang data KRS / state reaktif.
ionViewDidEnter Tepat SETELAH animasi transisi selesai. Auto-focus keyboard, pemutar media.

💻 Cara Menulis di Ionic Vue 3:

import { onIonViewWillEnter, onIonViewDidEnter } from '@ionic/vue';

onIonViewWillEnter(() => {
  console.log('🔄 Memuat ulang data KRS terbaru...');
  fetchDataMahasiswa();
});

onIonViewDidEnter(() => {
  console.log('✨ Layar siap, fokus ke input pertama.');
});

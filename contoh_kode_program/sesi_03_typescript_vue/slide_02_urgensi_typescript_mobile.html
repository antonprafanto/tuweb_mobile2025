Urgensi TypeScript: Mencegah Crash Fatal Runtime pada Aplikasi Mobile

Membandingkan kelemahan silent failure JavaScript murni vs perlindungan compile-time TypeScript.

1. JAVASCRIPT MURNI (DYNAMIC TYPING)

⚠️ Bencana Typo & Silent Failure

Ketika kita memanggil properti yang salah ketik (misal: mhs.ipkSemester tertulis mhs.ipkSmt), JavaScript tidak akan komplain saat ngoding. Tetapi saat kalkulasi, aplikasi menghasilkan nilai NaN!

Nama: {{ mhsJS.nama }}
Hasil Hitung Bobot: {{ hasilJS }}
// JavaScript Murni:
const mhs = { nama: 'Rani', ipk: 3.8 };

// Typo properti: mhs.skorIpk (tidak ada!)
const hasil = mhs.skorIpk * 25; 
// undefined * 25 = NaN (Aplikasi Rusak!)
2. TYPESCRIPT (STATIC TYPE CHECKING)

🛡️ Kontrak Data Mutlak (Interface)

TypeScript memaksa pengembang mendeklarasikan bentuk data (kontrak). Jika ada salah ketik 1 huruf saja, editor langsung memblokir kompilasi sebelum kode sempat dikirim ke smartphone!

Status Proteksi: ✅ Aktif (VS Code Intellisense)
Status Build: 0 Runtime Error Terdeteksi
// TypeScript Interface:
interface Mahasiswa {
  nama: string;
  ipk: number;
}

const mhs: Mahasiswa = { nama: 'Rani', ipk: 3.8 };

// ❌ COMPILE-TIME ERROR:
// Property 'skorIpk' does not exist on type 'Mahasiswa'!
console.log(mhs.skorIpk);

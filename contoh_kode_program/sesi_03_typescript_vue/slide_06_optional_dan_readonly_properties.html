SLIDE 06 • MODUL 3 BMP UT

Properti Opsional (?) dan Mutlak Tidak-Dapat-Diubah (readonly)

Menjaga integritas data identitas mahasiswa agar tidak termutasi secara tidak sengaja.

📘 PANDUAN PRAKTIKUM MAHASISWA

🛠️ Alat yang Digunakan: Google Chrome / Peramban Web Modern.

🎯 Cara Menguji Interaksi: Perhatikan kolom NIM yang berwarna abu-abu dan tidak dapat diedit karena dikunci dengan modifier readonly. Cobalah ketikkan nama Anda pada kolom kedua, lalu biarkan kolom ketiga (No HP) kosong. Perhatikan bahwa objek tetap valid karena No HP ditandai dengan tanda tanya (? opsional).

💡 Apa yang Terjadi di Balik Layar: Modifier readonly mencegah re-assignment nilai setelah objek diinisialisasi (misal: mhs.nim = '04123' akan langsung menghasilkan compile error). Sedangkan modifier tanda tanya ? mengizinkan nilai bernilai undefined tanpa memicu peringatan properti hilang.

📐 Perbandingan Modifier Properti: Gembok Readonly vs Fleksibilitas Opsional

🪪 Formulir Biodata Mahasiswa Terproteksi

🔒 Field ini diproteksi oleh TypeScript dengan kata kunci 'readonly'. NIM tidak boleh diubah setelah instansiasi!
Hasil Objek Data:
NIM: {{ mhs.nim }} | Nama: {{ mhs.nama }} | HP: {{ mhs.noHp || '(Belum Diisi / Undefined)' }}

💡 Perbedaan Sintaks TypeScript:

interface ProfilMahasiswa {
  readonly nim: string;     // 🔒 Tidak bisa di-assign ulang: mhs.nim = '049' ❌ ERROR
  nama: string;             // 📝 Wajib ada nilai saat inisialisasi
  noHp?: string;            // ❓ Opsional: boleh undefined
  emailKampus?: string;     // ❓ Opsional
}
